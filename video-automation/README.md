# Автоматизация роликов для бота «Photo LIKE | ИИ ФОТО»

Конвейер из четырёх скриптов: идея → фото по вашему лицу → оживление → готовый ролик.
Структура ролика повторяет референс `IMG_1645.MOV`:

```
[1] 1.7–2.8 с          [2] вся длина          [3] 1.6–2.6 с
оживлённое ИИ-фото  →  видеосреднее.mp4   →   итоговое фото
+ надпись-крючок       (постоянная часть)     + медленный зум + переход
```

Длительности каждый раз слегка разные, поэтому ролики не выглядят под копирку.

---

## Запуск — одна кнопка

Положите все файлы в папку `ВИТЯ АВТОМАТИЗАЦИЯ` и **дважды кликните `СТАРТ.command`**.
Или из терминала:

```bash
cd "/Users/aleksandrtomilov/Desktop/ВИТЯ АВТОМАТИЗАЦИЯ"
python3 СТАРТ.py
```

`СТАРТ` делает всё сам и в правильном порядке:

1. проверяет версию Python;
2. **доустанавливает недостающие библиотеки** (openai, requests, Pillow);
3. проверяет ffmpeg и предлагает поставить его через Homebrew, если нет;
4. проверяет ключи, при необходимости спрашивает и **сохраняет в `~/.zshrc`**,
   плюс делает тестовый запрос, чтобы поймать битый ключ до начала генерации;
5. проверяет фото лица, `видеосреднее.mp4`, папку мелодий и шрифт;
6. создаёт `ИДЕИ.txt` из образца, если его ещё нет;
7. чистит забракованные идеи;
8. досоздаёт идеи, если готовых не хватает;
9. прогоняет фото → оживление → монтаж;
10. показывает, что получилось.

Полезные флаги:

```bash
python3 СТАРТ.py --count 5      # сколько роликов сделать
python3 СТАРТ.py --yes          # ничего не спрашивать
python3 СТАРТ.py --only-check   # только проверить окружение
```

Перед съёмкой `СТАРТ` останавливается и предлагает посмотреть `ИДЕИ.txt` —
можно отказаться, поправить идеи руками и запустить заново.

Ключи берутся **оттуда же, откуда их брали старые скрипты** — из переменных
окружения `OPENAI_API_KEY` и `FAST_GEN_API_KEY`. Если они уже в `~/.zshrc`,
делать ничего не нужно.

## Что где лежит

| Путь | Что это |
|---|---|
| `ИДЕИ.txt` | все идеи, статусы и просмотры — единственный файл, который вы правите руками |
| `ЛИЦО/` | 3–4 ваших фото (анфас, полуоборот, разный свет) — чем больше, тем точнее сходство |
| `telegram-cloud-document-2-...jpg` | запасной вариант: одиночное фото лица, если папки `ЛИЦО` нет |
| `видеосреднее.mp4` | постоянная средняя часть (скринкаст бота) |
| `мелодии/` | музыка `1.mp3`, `2.mp3`, … — берётся случайная |
| `ФОТО/` `ВИДЕО/` `ГОТОВОЕ/` | результаты по шагам |
| `_кэш/` | профиль лица, аналитика, бэкапы `ИДЕИ.txt` |

Пути меняются в `config.py` (или через `export VITYA_BASE_DIR="..."`).

## Скрипты

### 1. `step1_ideas.py` — идеи и обучение на просмотрах

```bash
python3 step1_ideas.py                # добавить 5 новых идей
python3 step1_ideas.py --count 10
python3 step1_ideas.py --only-analyze # только аналитика, ничего не добавлять
python3 step1_ideas.py --clean        # забраковать уже лежащие плохие идеи
```

`--clean` прогоняет проверку по идеям со статусом `НОВАЯ`, которые уже лежат
в файле, и переводит неподходящие в статус `ОТКЛОНЕНА` — в работу они больше
не пойдут. Нужно после смены правил генерации, чтобы старые идеи не всплывали.

Читает `ИДЕИ.txt`. Если в поле `ПРОСМОТРЫ` где-то стоят числа — раскладывает
ролики от лучших к худшим и просит GPT вытащить конкретные сработавшие приёмы
(тип сцены, формула надписи, эмоция). Новые идеи генерирует **по этим паттернам**,
плюс 1–2 экспериментальные. Отчёт пишется в `_кэш/аналитика.txt`.

**Надпись всегда обещает результат зрителю или обещает научить** — как в референсе:

> «Как сделать такое же фото» · «Это фото разорвет твой директ» ·
> «После такого фото тебе будут писать первыми» ·
> «С таким фото на тебя точно обратят внимание»

Половина партии — формат инструкции, половина — формат обещания.
Надписи от первого лица («мама распечатала», «никто не поверил») запрещены —
они не обещают зрителю ничего.

**Сцены только бытовые и правдоподобные** — такие, какие реально можно случайно
снять на телефон: обнимается с гаишниками у патрульной машины, ведут по коридору
отдела, на плечах у футболистов после матча, за рулём скорой, в строю спецназа,
даёт интервью на улице. Экстрим, экзотика и глянцевая роскошь (парашют, тигр,
яхта, частный джет, красная дорожка) запрещены — они читаются как нейросеть.

На выходе стоит автопроверка: идеи с надписью от первого лица, со слишком длинной
надписью или с нереалистичной сценой отбраковываются и не попадают в файл
(в консоли видно, что и почему отсеяно). Поэтому у GPT запрашивается с запасом.

### 2. `step2_photo.py` — фото по вашему лицу

```bash
python3 step2_photo.py                # все идеи со статусом НОВАЯ
python3 step2_photo.py --limit 3
python3 step2_photo.py --idea 7
python3 step2_photo.py --backend fastgen
```

Генерирует вертикальное фото по сцене идеи, сохраняя ваше лицо.

**Чтобы лицо получалось похожим, положите 3–4 своих фото в папку `ЛИЦО`** —
анфас, полуоборот, разный свет. Модель держит внешность заметно точнее, чем
с одного снимка. Если папки нет, берётся одиночный файл из `config.py`.

Что сделано для сходства:

* запрос уходит с `input_fidelity: "high"` — именно этот параметр заставляет
  gpt-image-1 держать черты лица с исходника, а не рисовать похожего человека;
* в промпт зашит явный запрет «улучшать» внешность: делать моложе, стройнее,
  симметричнее, убирать морщины и родинки, менять нос, губы, причёску и бороду,
  наводить глянцевую ретушь;
* **словесное описание лица в промпт больше не подставляется.** Это было главной
  ошибкой: получив описание «мужчина 30–35 лет с тёмными волосами и бородой»,
  модель рисовала любого мужчину, подходящего под описание, вместо конкретного
  человека с фото. Теперь описание внешности используется только бэкендом
  `fastgen`, где картинку-референс передать нельзя.

Два бэкенда: `openai` (gpt-image-1 с вашими фото как референсом, по умолчанию)
и `fastgen` (api.fast-gen.ai).

### 3. `step3_animate.py` — оживление

```bash
python3 step3_animate.py
python3 step3_animate.py --workers 3
```

Механика ровно как в вашем рабочем скрипте: картинка → inline base64 в `inputs[]`
→ `flow_video_from_ingredients` → mp4. Промпт оживления **намеренно без сюжета** —
только лёгкое дыхание кадра, микродвижение головы и волос, еле заметный наезд
камеры. Никаких новых действий, чтобы лицо не «поплыло».

Safety-блокировки не повторяются (идея просто помечается и скрипт идёт дальше),
временные ошибки — до 4 попыток.

### 4. `step4_montage.py` — сборка

```bash
python3 step4_montage.py
python3 step4_montage.py --idea 7
python3 step4_montage.py --crossfade   # с плавным переходом на финальное фото
```

Порядок частей жёсткий: хук с надписью → `видеосреднее.mp4` → **итоговое фото,
то самое, из которого делалось оживлённое видео**. Склейка по умолчанию встык,
как в референсе. После сборки скрипт сверяет длину ролика с суммой частей и
ругается, если хвост потерялся, — молча выпустить ролик без финального фото он
не может. Длительность каждой части печатается в консоли.

Если в вашей сборке ffmpeg нет `xfade` или `zoompan`, скрипт это заметит и
соберёт ролик без перехода / без зума, но **все три части останутся на месте**.

Приводит всё к 1080×1920/30fps, накладывает надпись (белая, жирная, чёрная обводка
и мягкая тень, по центру в верхней трети — как в референсе), собирает три части,
делает кроссфейд на финальное фото и подкладывает случайную мелодию: **начало трека
сохраняется, лишнее режется с конца**, в конце фейд.

Размер шрифта и перенос строк подбираются автоматически под длину надписи.

Надпись рисуется через Pillow в прозрачный PNG и накладывается фильтром `overlay`,
поэтому **работает на любой сборке ffmpeg** — в том числе собранной без libfreetype,
где нет фильтра `drawtext`. Если Pillow не установлен, скрипт сам переключается на
`drawtext`, а если нет и его — говорит, что поставить.

### Всё сразу

```bash
python3 СТАРТ.py --count 3         # с проверками и установкой библиотек
python3 run_all.py --skip-ideas    # без проверок, по уже придуманным идеям
```

## Рабочий цикл

```
СТАРТ  →  глазами проверить ИДЕИ.txt на паузе, лишнее поправить
       →  фото → оживление → монтаж (автоматически)
       →  опубликовать
       →  вписать ПРОСМОТРЫ в ИДЕИ.txt
       →  СТАРТ снова — идеи уже по сработавшим паттернам
```

## Формат ИДЕИ.txt

```
═══ ИДЕЯ 001 ═══
СТАТУС: НОВАЯ
НАЗВАНИЕ: Задержание в суде
НАДПИСЬ: Как сделать фото, которое разорвет директ
ОПИСАНИЕ: Мужчину в наручниках ведут по коридору суда.
ПРОМПТ_ФОТО: Мужчина с короткими тёмными волосами...
ПРОСМОТРЫ: 45000
ФОТО_ФАЙЛ:
ВИДЕО_ФАЙЛ:
РОЛИК_ФАЙЛ:
ДАТА:
```

* `ПРОСМОТРЫ` заполняете вы. Понимает `45000`, `45 000`, `45k`, `1.2M`, `45тыс`.
* `СТАТУС` ведут скрипты: `НОВАЯ → ФОТО → ВИДЕО → СНЯТА`.
  **`СНЯТА` = идея полностью отработана**, повторно она не берётся.
* Порядок полей и регистр не важны, многострочные значения пишутся с отступом.
* Перед каждой перезаписью делается бэкап в `_кэш/бэкапы_идей/`.

Чтобы переснять идею — поменяйте её статус обратно на `НОВАЯ`.
