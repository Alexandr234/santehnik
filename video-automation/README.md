# Автоматизация роликов для бота «Photo LIKE | ИИ ФОТО»

Конвейер из четырёх скриптов: идея → фото по вашему лицу → оживление → готовый ролик.
Структура ролика повторяет референс `IMG_1645.MOV`:

```
[1] 1.7–2.8 с          [2] вся длина          [3] 1.6–2.6 с
оживлённое ИИ-фото  →  видеосреднее.mp4   →   итоговое фото
+ надпись-крючок       (постоянная часть)     + медленный зум + переход
```

Длительности каждый раз слегка разные, поэтому ролики не выглядят под копирку.

```bash

```

## Что где лежит

| Путь | Что это |
|---|---|
| `ИДЕИ.txt` | все идеи, статусы и просмотры — единственный файл, который вы правите руками |
| `telegram-cloud-document-2-...jpg` | ваше лицо, эталон для всех генераций |
| `видеосреднее.mp4` | постоянная средняя часть (скринкаст бота) |
| `мелодии/` | музыка `1.mp3`, `2.mp3`, … — берётся случайная |
| `ФОТО/` `ВИДЕО/` `ГОТОВОЕ/` | результаты по шагам |
| `_кэш/` | профиль лица, аналитика, бэкапы `ИДЕИ.txt` |

Пути меняются в `config.py` (или через `export VITYA_BASE_DIR="..."`).

## Скрипты

### 1. `step1_ideas.py` — идеи и обучение на просмотрах

```bash
python3 step1_ideas.py                # добавить 5 новых идей
python3 step1_ideas.py --count 10
python3 step1_ideas.py --only-analyze # только аналитика, ничего не добавлять
```

Читает `ИДЕИ.txt`. Если в поле `ПРОСМОТРЫ` где-то стоят числа — раскладывает
ролики от лучших к худшим и просит GPT вытащить конкретные сработавшие приёмы
(тип сцены, формула надписи, эмоция). Новые идеи генерирует **по этим паттернам**,
плюс 1–2 экспериментальные. Отчёт пишется в `_кэш/аналитика.txt`.

**Надпись всегда обещает результат зрителю или обещает научить** — как в референсе:

> «Как сделать такое же фото» · «Это фото разорвет твой директ» ·
> «После такого фото тебе будут писать первыми» ·
> «С таким фото на тебя точно обратят внимание»

Половина партии — формат инструкции, половина — формат обещания.
Надписи от первого лица («мама распечатала», «никто не поверил») запрещены —
они не обещают зрителю ничего.

**Сцены только бытовые и правдоподобные** — такие, какие реально можно случайно
снять на телефон: обнимается с гаишниками у патрульной машины, ведут по коридору
отдела, на плечах у футболистов после матча, за рулём скорой, в строю спецназа,
даёт интервью на улице. Экстрим, экзотика и глянцевая роскошь (парашют, тигр,
яхта, частный джет, красная дорожка) запрещены — они читаются как нейросеть.

На выходе стоит автопроверка: идеи с надписью от первого лица, со слишком длинной
надписью или с нереалистичной сценой отбраковываются и не попадают в файл
(в консоли видно, что и почему отсеяно). Поэтому у GPT запрашивается с запасом.

### 2. `step2_photo.py` — фото по вашему лицу

```bash
python3 step2_photo.py                # все идеи со статусом НОВАЯ
python3 step2_photo.py --limit 3
python3 step2_photo.py --idea 7
python3 step2_photo.py --backend fastgen
```

Один раз отправляет ваше фото в GPT-4o vision и получает описание внешности
(кэшируется в `_кэш/профиль_лица.json`). Дальше для каждой идеи собирает промпт
«внешность + сцена» и генерирует вертикальное фото.

Два бэкенда: `openai` (gpt-image-1 с вашим фото как референсом — лучше держит лицо,
стоит по умолчанию) и `fastgen` (ваш привычный api.fast-gen.ai).

### 3. `step3_animate.py` — оживление

```bash
python3 step3_animate.py
python3 step3_animate.py --workers 3
```

Механика ровно как в вашем рабочем скрипте: картинка → inline base64 в `inputs[]`
→ `flow_video_from_ingredients` → mp4. Промпт оживления **намеренно без сюжета** —
только лёгкое дыхание кадра, микродвижение головы и волос, еле заметный наезд
камеры. Никаких новых действий, чтобы лицо не «поплыло».

Safety-блокировки не повторяются (идея просто помечается и скрипт идёт дальше),
временные ошибки — до 4 попыток.

### 4. `step4_montage.py` — сборка

```bash
python3 step4_montage.py
python3 step4_montage.py --idea 7
python3 step4_montage.py --no-crossfade
```

Приводит всё к 1080×1920/30fps, накладывает надпись (белая, жирная, чёрная обводка
и мягкая тень, по центру в верхней трети — как в референсе), собирает три части,
делает кроссфейд на финальное фото и подкладывает случайную мелодию: **начало трека
сохраняется, лишнее режется с конца**, в конце фейд.

Размер шрифта и перенос строк подбираются автоматически под длину надписи —
через точный замер ширины (Pillow), с запасным вариантом если Pillow не стоит.

### Всё сразу

```bash
python3 run_all.py --count 3
python3 run_all.py --skip-ideas    # по уже придуманным идеям
```

## Рабочий цикл

```
step1  →  глазами проверить ИДЕИ.txt, лишнее удалить/поправить
       →  step2 → step3 → step4
       →  опубликовать
       →  вписать ПРОСМОТРЫ в ИДЕИ.txt
       →  step1 снова — идеи уже по сработавшим паттернам
```

Отсматривать идеи перед съёмкой удобнее, запуская шаги по отдельности, а не `run_all.py`.

## Формат ИДЕИ.txt

```
═══ ИДЕЯ 001 ═══
СТАТУС: НОВАЯ
НАЗВАНИЕ: Задержание в суде
НАДПИСЬ: Как сделать фото, которое разорвет директ
ОПИСАНИЕ: Мужчину в наручниках ведут по коридору суда.
ПРОМПТ_ФОТО: Мужчина с короткими тёмными волосами...
ПРОСМОТРЫ: 45000
ФОТО_ФАЙЛ:
ВИДЕО_ФАЙЛ:
РОЛИК_ФАЙЛ:
ДАТА:
```

* `ПРОСМОТРЫ` заполняете вы. Понимает `45000`, `45 000`, `45k`, `1.2M`, `45тыс`.
* `СТАТУС` ведут скрипты: `НОВАЯ → ФОТО → ВИДЕО → СНЯТА`.
  **`СНЯТА` = идея полностью отработана**, повторно она не берётся.
* Порядок полей и регистр не важны, многострочные значения пишутся с отступом.
* Перед каждой перезаписью делается бэкап в `_кэш/бэкапы_идей/`.

Чтобы переснять идею — поменяйте её статус обратно на `НОВАЯ`.
